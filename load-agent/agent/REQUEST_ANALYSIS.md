# Разбор запроса пользователя → сценарий нагрузки

Развёрнутый промпт для шага 0 конвейера. Читай его, когда запрос пользователя сложнее,
чем «прогони нагрузку на URL X»: есть списки данных, файлы, требования к содержимому
ответов, запись, внешние хосты — или когда чего-то из обязательного не хватает.

## Таблица извлечения

Пройди по каждой строке и выпиши значение из запроса пользователя. Не придумывай —
если в запросе нет и дефолт не разрешён, значение = «СПРОСИТЬ».

| # | Что извлечь | Куда идёт в сценарии | Если не сказано |
|---|---|---|---|
| 1 | Цель: схема://хост:порт | `baseUrl` | СПРОСИТЬ |
| 2 | Эндпоинты: метод + путь + параметры | `requests[].method/path` | СПРОСИТЬ или взять из готового сценария |
| 3 | Частотность: что чаще, что реже | `requests[].weight` | все weight = 1 |
| 4 | Авторизация: логин/пароль или токен | `auth` | probe покажет: если 401 → СПРОСИТЬ креды |
| 5 | Данные-списки: перечислены в тексте? | `vars.<имя>: [значения]` | — |
| 6 | Данные-файлы: упомянут файл .txt/.csv/.json? | `vars.<имя>: { "file": "путь", "column"?: "...", "extract"?: "..." }` | — |
| 7 | Динамические данные с сервера («по всем пулам») | `vars.<имя>: { "setupPath": "...", "extract": "..." }` | — |
| 8 | Проверки содержимого ответа | `requests[].checks` | только статусы (дефолт) |
| 9 | Бюджет времени на запрос («не дольше 300мс») | `requests[].checks.maxMs` | — |
| 10 | Профиль нагрузки: пользователи/RPS/длительность | `load.vus / maxRps / durationSec` | vus 5, 30с |
| 11 | Критерии успеха («p95 меньше 200мс», «без ошибок») | `thresholds` | p95Ms 1000, errorRatePct 1 |
| 12 | Разрешение на запись (POST/PUT/DELETE) | `allowWrites` + флаг `--allow-writes` | НЕТ записи |
| 13 | Внешний хост — подтверждено, что свой? | флаг `--confirm-external` | НЕ запускать, СПРОСИТЬ |

## Правила

- **Строки 1–2 обязательны.** Без них не запускай ничего, кроме probe. Одного URL достаточно,
  чтобы сделать probe и вернуться с вопросом.
- **Слова-маркеры списков**: «по каждому», «по всем», «для этих ID», «из файла», «перебери» →
  это vars. Выбирай источник: значения в тексте → массив; файл → file; «все N с сервера» → setupPath.
- **Слова-маркеры проверок**: «проверь что возвращается», «должен содержать», «валидный JSON»,
  «поле X = Y», «непустой ответ» → это checks (bodyContains / jsonPath / jsonPathEquals / notEmpty).
- **СПРОСИТЬ ≠ пытать вопросами.** Собери ВСЕ недостающие пункты и задай одним сообщением.
- **Ничего не проси дважды**: если пользователь дал токен — не проси логин.
- **Файлы пользователя не переписывай** — подключай через vars.file как есть; пути в сценарии
  указывай относительно папки сценария.

## Примеры

### Пример 1 — простой
Запрос: «Нагрузи http://localhost:8080, эндпоинты api/v1/pools и api/v1/tokens, логин ivanov@example.com / Demo1234»

Извлечение: baseUrl ✓, 2 GET-запроса ✓, auth=login ✓, остальное — дефолты.
→ Сценарий без vars и checks, weight 1/1, load { vus: 5, durationSec: 30 }. Вопросов нет.

### Пример 2 — списки из файла + проверки
Запрос: «Прогони по всем пулам из файла C:\data\pools.txt деталку /api/v1/pools/{id},
ответ должен содержать activeBinId и приходить быстрее 300мс. 20 пользователей, 2 минуты»

Извлечение:
- vars: `"poolId": { "file": "C:/data/pools.txt" }` (абсолютный путь допустим)
- request: path `/api/v1/pools/{{poolId}}`,
  checks: `{ "jsonPath": "activeBinId", "maxMs": 300 }`
  (если jsonPath не дал значений на смоуке — посмотри тело ответа и уточни путь, например `pool.activeBinId`)
- load: `{ "vus": 20, "durationSec": 120 }`
- auth не назван → probe покажет; если 401 — один вопрос про креды.

В отчёте будет секция «ВЛИЯНИЕ ПАРАМЕТРОВ» — обязательно перескажи её пользователю:
какие ID из его файла медленные/ошибочные.

### Пример 3 — запись и внешний хост (нужны подтверждения)
Запрос: «Постреляй свопами в тестовый стенд 141.105.65.29»

Извлечение: swap = POST → запись; 141.105.65.29 → внешний хост; эндпоинт и тело свопа не даны.
→ ОДНИМ сообщением спроси: 1) подтверждение, что стенд ваш и тест согласован
(нужно для --confirm-external); 2) подтверждение записи в него (--allow-writes);
3) точный эндпоинт и пример тела свопа; 4) креды.
Ничего не запускай до ответа, кроме probe.
