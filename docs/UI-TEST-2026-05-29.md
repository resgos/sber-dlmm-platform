findings, all on **how values are aggregated**, none a render/crash bug. All four

## Findings & fixes

### F-09 🔴 — fee → ₽ roll-ups show "0 ₽" everywhere (systemic)
**Where:** user Dashboard hero, user Positions KPI, user Profile; admin Dashboard
(«Комиссия за всё время» + «Собрано комиссий»).
**Reality:** DB has real fees. SBTC pool alone holds `total_fees_collected_y =
4 576 884 577` (4.58 млрд). ivanov has 33 unclaimed accruals (Σ 254 308 373) +
34 claimed (Σ 195 715 154). Per-position amounts render fine; only the summed
₽ figure was 0.
**Two independent root causes:**
1. **Admin dashboard** — `AdminService` sums `p.get("totalFeesCollectedX/Y")` from
   the pool-engine `/pools` JSON, but `PoolResponse` (list DTO) never exposed those
   fields (only `PoolDetailResponse` did) → key missing → `toBigDecimal(null)=0` →
   `totalFeesCollectedRub: 0`. (TVL/volume worked because `PoolResponse` *does*
   carry `totalTvlX/Y` + `volume24h`.)
2. **User KPIs** — DTO contract mismatch. FE `FeeSummary` reads `totalEarnedX/Y`,
   `totalClaimed`, `totalUnclaimed`; BE `/fees/me/summary` returned only
   `totalUnclaimedX`/`totalUnclaimedY` + `byPool`. FE `feeSummary.totalUnclaimed`
   was `undefined` → `?? 0` → "0 ₽" on 3 pages.
**Fix:**
- `PoolResponse` + `PoolService` (both mappers): add + populate
  `totalFeesCollectedX/Y`. admin-bff aggregation already reads these keys.
- `FeesSummaryResponse` + `FeeService.getUserFeesSummary`: add `totalEarnedX/Y`,
  `totalClaimed`, `totalUnclaimed` (combined cross-token, same smallest-unit-as-₽
  proxy the admin dashboard already uses for TVL; precise per-token split stays in
  `byPool`). Zero frontend change — honors the existing FE contract.
**Verification:** _pending backend redeploy (in progress)_

### F-11 🟠 — admin Pools stat cards summed only the current page → ✅ FIXED
**Where:** admin `/pools` KPI tiles.
**Root cause:** `PoolsPage` aggregated over `data.content` (the paginated 20 rows),
silently dropping the SBTC flagship (~1.59 трлн, 99.9% of volume) → «TVL 182 млрд»
vs Dashboard's «2.31 трлн».
**Fix:** added a second cached full-set query (`getPools(0,200)`) to drive the
tiles; the paginated query still drives the table.
**Verified:** tiles now show **22/22, TVL 2.31 трлн, Объём 1.50 трлн, APY 5.99%** —
match the Dashboard. Table still paginates (20 из 22).

### F-10 🟡 — admin Users «Последний вход» always "—"
**Where:** admin `/users` table.
**Reality:** DB `last_login_at` is populated (admin 12:07, ivanov 12:02 — the
login flow sets it). Column showed "—" for everyone.
**Root cause:** `/users` returns `UserProfileResponse`, which omitted `lastLoginAt`
(the column + login-flow population were added in Batch #6, but the DTO was never
extended). admin-bff `/users` is a pass-through proxy, so the field never reached
the UI.
**Fix:** add `lastLoginAt` to `UserProfileResponse` + its single mapper
(`UserService.toProfileResponse`).
**Verification:** _pending backend redeploy (in progress)_
