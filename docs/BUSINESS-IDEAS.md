# Бизнес-идеи — Sber DLMM

Бэклог продуктовых/монетизационных гипотез для платформы концентрированной
ликвидности (рынок РФ, эталон UX — Meteora). Каждая идея: **ценность →
монетизация → усилие (S/M/L)** + что переиспользуем из уже построенного движка.
Не план — гипотезы для приоритизации.

---

## 2026-06-17

### Идея: AML-детектор структурирования переводов (smurfing)
Наблюдение тика: все 4 флага — SWAP; детекторы (TVL-доля, частота, импакт)
заточены под свопы, а классика отмывания — TRANSFER: дробление суммы на много
мелких переводов под порогом. Детектор: N переводов от/к юзеру за окно, каждый
< порога, суммарно > лимита → флаг «структурирование».
- **Ценность:** закрывает слепую зону комплаенса по самому «отмывочному» типу
  операций; профильный кейс 115-ФЗ.
- **Монетизация:** risk/compliance-модуль (ENTERPRISE).
- **Усилие: M.** Скан уже группирует по userId; добавить группировку по типу
  TRANSFER с суммой/счётчиком; пороги в конфиг. Пара к category-полю флага.

### Идея: Контекст-дроуэр флага (транзакция + досье юзера в один клик)
Сейчас офицер видит строку флага и кнопку «Просмотрено» — решение приходится
принимать вслепую или идти искать юзера руками. Клик по флагу → дроуэр: детали
транзакции, мини-досье (KYC-статус, возраст аккаунта, частота за неделю,
прошлые флаги), кнопки «Ложное/Эскалация» там же.
- **Ценность:** решение по флагу за секунды в одном экране — ядро UX
  комплаенс-инструмента; меньше ошибок ревью.
- **Монетизация:** risk/compliance-модуль; премиум для банков.
- **Усилие: M.** Данные есть (transactions/{id}, admin users/{id}, флаги);
  один Drawer-компонент + 2-3 запроса. Пара к «диспозиции при Просмотрено».

### Идея: Выгрузка AML-флагов в формате Росфинмониторинга (ФЭС)
CSV/PDF — для внутреннего пользования; регулятору нужен формализованный
электронный формат (ФЭС 115-ФЗ). Маппинг полей флага → структура сообщения
(тип операции, суммы, стороны, признак) + валидация обязательных полей.
- **Ценность:** «нажал — получил файл для Росфина» — прямое попадание в
  регуляторный процесс банка; сильный аргумент enterprise-продажи.
- **Монетизация:** compliance-модуль ENTERPRISE; сопровождение форматов.
- **Усилие: M–L.** Формат публичный, но объёмный; начать с подмножества полей
  демо-данных + XML/структурный экспорт. Требует category/диспозиции (пары выше).

### Идея: Честный fee-APY из эффективной ставки (кросс-чек заявленного APY)
fee-stats теперь отдаёт фактическую ставку по свопам пула. Повернуть её к LP:
`факт. ставка × оборот / TVL` = реализованный fee-APY — сверять с витринным APY
пула и показывать бейдж «подтверждено сделками» / «расчётный». Расхождение —
сигнал (сид-данные, мёртвый пул, завышенная витрина).
- **Ценность:** доверие инвестора: APY, подкреплённый реальными сделками, а не
  моделью; сам себе аудит витрины.
- **Монетизация:** прозрачность как фича ENTERPRISE-отчётности для LP.
- **Усилие: M.** Данные есть (fee-stats + volume24h + TVL); формула на фронте
  или в BFF; бейдж в KPI пула. Пара к apyProvenance (уже показывает live/model).

### Идея: Алерт «эффективная ставка пула изменилась» (LP и трейдеру)
Разово ставку видно на детали пула; следить вручную никто не будет. Алерт по
порогу: трейдеру — «ставка выросла ×K, подожди с крупным свопом», LP —
«волатильность подняла ставку — зарабатываешь больше обычного».
- **Ценность:** превращает новый датчик в проактивный сигнал; удержание обеих
  аудиторий (трейдер экономит, LP видит момент дохода).
- **Монетизация:** premium-алерты (пакет с position-alerts).
- **Усилие: S–M.** Фронт-вотчер positionAlertsStore уже опрашивает пулы —
  добавить тип правила «eff-fee vs base»; бэкенд не нужен (fee-stats публичный).

### Идея: Batch fee-stats + кэш (готовность к карточкам списка пулов)
Сейчас fee-stats зовётся по одному пулу. Если вывести ставку на карточки
PoolsPage (20+ пулов), будет N запросов на рендер. Batch-эндпоинт
`?poolIds=...` (один GROUP BY) + Redis-кэш 60с (стек уже есть) — до того, как
это станет проблемой.
- **Ценность:** держит p95 списка пулов при масштабировании фичи на витрину;
  дешёвая страховка перфоманса.
- **Монетизация:** не прямая — перф/стоимость инфраструктуры.
- **Усилие: S–M.** SQL: fee_rate по последним N на пул через LATERAL/оконку;
  кэш-аннотация. Делать ВМЕСТЕ с выводом ставки в список (не раньше).

### Идея: Нижняя таб-навигация на мобилке (стандарт банковских приложений)
На телефоне навигация сейчас как на десктопе (верхнее меню) — большие пальцы

- **Монетизация:** не прямая — мобильная конверсия/удержание.
- **Усилие: M.** Компонент BottomNav (fixed, safe-area-inset), показывать <md;

### Идея: PWA — установка на домашний экран + офлайн-заглушка
Демо открывается в браузере; PWA-манифест + сервис-воркер дают «Установить
приложение» (иконка на домашнем экране, полноэкранный режим без адресной

приложение» без затрат на нативную разработку.
- **Ценность:** wow-эффект демо с телефона + шаг к пуш-уведомлениям
  (web-push) без App Store.
- **Монетизация:** удержание (иконка на экране = возвраты); канал пушей.
- **Усилие: S–M.** vite-plugin-pwa: манифест (иконки уже есть — Сберкот),
  воркер с офлайн-фолбэком; без изменений бэкенда.

### Идея: Локализация ошибок бэкенда по кодам (EN-юзер видит русские ошибки API)
Регистрация/логин теперь двуязычные, но `setError` предпочитает
`response.data.message` от бэкенда — а он приходит ПО-РУССКИ («Пользователь уже
существует»). EN-инвестор в EN-форме получает русскую ошибку. Фикс-паттерн:
бэкенд уже шлёт машинный код (`DlmmException` error code) — фронт мапит код →
локализованный текст, `message` бэка остаётся фолбэком.
- **Ценность:** сквозная двуязычность серверных ошибок во ВСЕХ формах (регистрация,
  своп, ликвидность) — без перевода строк на бэкенде; ошибки станут и дружелюбнее.
- **Монетизация:** не прямая — целостность EN-UX для иностранного демо.
- **Усилие: S–M.** Карта `errors.<code>` в локалях + хелпер `apiErrorMessage`
  (уже есть — расширить чтением кода); бэкенд не трогаем.

### Идея: Живой чеклист требований к паролю на регистрации
Требования к паролю сейчас видны только ПОСЛЕ ошибки валидации (8+ символов,
буквы+цифры). Показываем под полем живой чеклист с галочками, обновляющийся по
мере ввода — стандарт банковских онбордингов.
- **Ценность:** меньше фрустрации на самом критичном шаге воронки (регистрация);
  прозрачные требования = меньше брошенных форм.
- **Монетизация:** конверсия регистраций (вершина воронки).
- **Усилие: S.** Чистый фронт: 3 предиката по значению поля + Space с иконками;
  ключи в `auth.register.*`. Отличается от «онбординг-чеклиста первых действий»
  (тот — после входа, про действия в продукте).

### Идея: Кнопка «Войти через Сбер ID» (SAML) на логине/регистрации
В кодовой базе уже есть `SamlCallbackPage` — SAML-мост частично проложен, но на
формах входа/регистрации нет кнопки SSO. Доводим: «Войти через Сбер ID» →
редирект на IdP → колбэк уже умеет принять ответ.
- **Ценность:** вход в один клик корпоративной учёткой Сбера — киллер-фича для
  внутрибанковского демо; меньше паролей = меньше поддержки.
- **Монетизация:** снижение трения онбординга сотрудников/клиентов банка;
  enterprise-готовность.
- **Усилие: M (флагать при реализации — auth-путь).** Кнопка + конфиг IdP-URL;
  колбэк-страница есть. Не путать с B2B SSO-мостом счетов (та идея — про
  интеграцию балансов).

### ✅ Идея: Метрика «утилизация капитала» + нудж разместить свободный остаток — реализовано 2026-06-17
Хиро теперь честно показывает кошелёк+LP (этот тик), и стало видно: у демо-юзера
в работе ~0.006% портфеля (411 млн из 6.3 трлн) — весь капитал простаивает в

X ₽ не работают — разместить в пул / YSRUB».
- **Ценность:** переводит наблюдение в действие — рост TVL платформы напрямую;
  пользователю — пассивный доход с простаивающего остатка.
- **Монетизация:** прямая — комиссии платформы растут с TVL; вход в YSRUB.
- **Усилие: S.** Обе суммы уже посчитаны в хиро (`totalBalanceRub`, `deployedRub`);
  метрика + CTA-строка. Отличается от «парковки корпоративного SRUB» (та — про
  курируемые пулы B2B) и от «кликабельных KPI» (та — про навигацию).

### ✅ Идея: CI-гард «мёртвые i18n-ключи» (документация, которая врёт) — реализовано 2026-06-17
Находка тика: `hero.tooltips.portfolio` существовал в обеих локалях и ДОКУМЕНТИРОВАЛ
семантику («кошелёк + LP»), но нигде не рендерился — а код считал иначе. Гард:
ключи, которые есть в локалях, но не упоминаются в .tsx/.ts (`t('...')`), — падают
списком (с whitelist динамически собираемых, напр. `glossary.${term}`).
- **Ценность:** ловит класс «копирайт написан, но не подключён» и «тултип врёт
  относительно кода» — дешёвая страховка консистентности текстов и семантики.
- **Монетизация:** не прямая — качество; дополняет locale-parity гард (тот про
  дыры МЕЖДУ локалями, этот — про неиспользуемое В локалях).
- **Усилие: S.** Скрипт: плоские ключи из ru.json − статические `t()`-литералы из
  исходников − whitelist шаблонных префиксов; в `lint:all`.
Проверено на живых данных: у 11 из 14 активных позиций демо-юзера
`initial_deposit_x/y = 0` (открыты до миграции 011) → колонка P&L и любой
портфельный ROI показывают «—». Сид/бэкафилл, проставляющий разумный
`initial_deposit` legacy-позициям (из истории ADD_LIQUIDITY-транзакций или
оценкой по текущей стоимости), даёт P&L полное покрытие.
- **Ценность:** P&L и доходность перестают быть наполовину пустыми — ключевая
  LP-метрика работает для всех, а не для трёх позиций; чище демо.
- **Монетизация:** не прямая — качество портфельной аналитики (PRO).
- **Усилие: M.** Идемпотентный сид по `transactions` (ADD_LIQUIDITY суммы) или
  фолбэк = текущая стоимость; не трогать денежный путь. Пара к плитке «Стоимость
  позиций» (этот тик) и к realized-APY.

### Идея: Портфельная плитка «Чистый результат» (внесено → стоимость + комиссии)
«Стоимость позиций» (этот тик) показывает ТЕКУЩУЮ стоимость, но не итог: чистый
результат LP = (стоимость сейчас − внесено) + забранные + незабранные комиссии.
Добавляем плитку/полосу «Чистый результат, ₽ и %» по всему портфелю.
- **Ценность:** один честный ответ «я в плюсе или в минусе как LP» с учётом и
  переоценки, и комиссий — то, чего нет ни на одной розничной DEX-витрине.
- **Монетизация:** PRO-аналитика портфеля; удержание (видят, что зарабатывают).
- **Усилие: S–M (зависит от backfill).** Стоимость уже считаем (`portfolioValueQuote`),
  комиссии в `feeSummary`; нужен корректный «внесено» (см. бэкафилл legacy выше).

### Идея: Бейдж «доля портфеля %» в строке позиции (концентрация)
Стоимость портфеля теперь известна — показать у каждой позиции её ДОЛЮ
(`valueQuote / portfolioValueQuote`), напр. «32% портфеля». LP сразу видит
перекос концентрации в один пул/пару.
- **Ценность:** риск-обзор «не сижу ли я на 80% в одном пуле» в один взгляд;
  основа для подсказок по диверсификации.
- **Монетизация:** PRO риск-аналитика; вход в авто-ребаланс.
- **Усилие: S.** Чистый фронт: `positionValueQuote` уже есть (этот тик) + сумма по
  портфелю; бейдж/мини-бар в строке. Без бэкенда.

### Идея: Серверный /admin/users/summary — глобальная KYC-воронка (не по странице)
KPI-плитки на «Пользователях» (всего/верифицировано/на проверке/доля KYC) считаются
по ТЕКУЩЕЙ странице (≤20 строк) — на проде с тысячами юзеров цифры врут. Делаем
лёгкий эндпоинт `/admin/users/summary` (агрегаты по всей таблице) и берём KPI из него.
- **Ценность:** честные глобальные показатели верификации/воронки для комплаенс-обзора,
  а не «по первой странице»; снимает документированный костыль.
- **Монетизация:** часть админ/risk-дашборда (ENTERPRISE-отчётность).
- **Усилие: M.** SQL `GROUP BY kyc_status` + endpoint в user-service/admin-bff; фронт
  читает summary вместо локального reduce. Пара к идее «реальная блокировка» (та про DTO).

### Идея: Бейдж активности юзера в админ-таблице (новый / спящий)
В таблице уже есть «Последний вход» и «Дата создания», но это сырые даты — админ не
видит паттерн с ходу. Добавляем бейдж: «новый» (создан <7 дней), «спит» (не входил

- **Ценность:** мгновенный взгляд на вовлечённость/риск оттока без отдельной страницы;
  основа для таргетных кампаний (welcome / win-back).
- **Монетизация:** growth-инструмент; вход в когорты/ретеншн-аналитику.
- **Усилие: S.** Чистый фронт по `createdAt`/`lastLoginAt` (уже в ответе) + бейдж-хелпер;
  пороги в конфиг. Пара к серверному summary и к когортам.

### Идея: Авто-напоминание о незавершённом KYC (конверсия + комплаенс)
Юзеры в статусе PENDING/NOT_SUBMITTED застревают на полпути — никто не подталкивает.
Шлём напоминание (нотификация/почта) «завершите верификацию», порционно и с
кулдауном; админу — счётчик «застрявших» и причина.
- **Ценность:** растит KYC-конверсию (прямой доход — верифицированные торгуют) и
  закрывает комплаенс-хвост; «доля KYC» (этот тик) перестаёт быть просто цифрой.
- **Монетизация:** конверсия в активных юзеров; growth/нудж-механика.
- **Усилие: M.** Выборка по kyc_status + notification-service шаблон (idempotency/
  кулдаун уже есть) + опционально e-mail. Не трогать денежный путь.

### Идея: Пред-своп предупреждение «динамическая комиссия сейчас повышена»
Индикатор повышенной комиссии в ленте (этот тик) показывает переплату ПОСТ-фактум.
Логичное продолжение — предупреждать ДО свопа: на панели свопа маленький бейдж
«базовая 25 bps → сейчас ~60 bps» когда volatility-accumulator пула поднял
переменную комиссию. Пользователь видит «момент дорогой» и может подождать.
- **Ценность:** превентивная экономия (а не «постфактум увидел, что переплатил») —
  ровно то, чем умная витрина бьёт сырой DEX; обучает природе динамической комиссии.
- **Монетизация:** premium-исполнение/«лучшее окно»; вход в smart-routing и алерты.
- **Усилие: M.** Переменная комиссия уже считается в pool-engine (аккумулятор есть) —
  отдать текущую эффективную ставку в quote/в pool detail + бейдж на свопе. Пара к
  пер-строчному индикатору (тот — постфактум, этот — до сделки).

### Идея: Разбор комиссии по клику на свопе в ленте (база + переменная + бины)
Флаг повышенной комиссии говорит «дороже обычного», но не РАЗБИВАЕТ почему. По клику
на строку свопа — поповер/дровер: базовая ставка пула, переменная надбавка,
сколько бинов пересёк (`binsCrossed` уже в ответе), итоговая эффективная ставка и
сумма «сверх базы» в ₽.
- **Ценность:** превращает «почему так дорого?» в прозрачный разбор — снижает тикеты
  в поддержку и обучает; естественное продолжение индикатора этого тика.
- **Монетизация:** premium-аналитика затрат; доверие/онбординг.
- **Усилие: S–M.** Данные в строке (`feeRate`, `feeAmount`, `binsCrossed`) + base из
  пула (уже грузим список); только новый компонент-разбор, без бэкенда.

### Идея: Фильтр ленты «только повышенная комиссия»
Индикатор красит дорогие свопы, но найти ИХ ВСЕ среди сотен строк нельзя — глазами
по странице. Добавляем фильтр-тумблер «только повышенная/высокая комиссия»
(предикат `fee_rate >= base*1.5` на бэке, как в индикаторе) рядом с фильтрами типа/
статуса/пула.
- **Ценность:** аналитик/активный трейдер одним кликом видит все свои дорогие сделки
  за период — для разбора и сверки; пара к сортировке по ставке (та — порядок).
- **Монетизация:** часть PRO-аналитики истории/затрат.
- **Усилие: M.** Бэкенд-предикат в transaction-service (Specification уже есть) +
  чекбокс в фильтрах; порог общий с индикатором (вынести в конфиг, чтобы не дрейфовал).

### Идея: Учебный центр — отдельная страница-глоссарий из тех же терминов
Контент глоссария теперь централизован и двуязычен (`glossary.*`, ru+en), но
доступен только точечно — навёл на термин в контексте. Новичок/инвестор часто
хочет «прочитать всё разом». Собираем `GLOSSARY_TERMS` в отдельную страницу
«Учебный центр» (карточки термин→определение→пример, поиск, якоря) и линкуем из
онбординга и футера.
- **Ценность:** образовательная витрина «как у Meteora» одним экраном — то, что
  снижает порог входа и хорошо смотрится в инвест-демо; ноль нового контента.
- **Монетизация:** не прямая — онбординг/доверие; SEO-страница под РФ-DeFi-запросы.
- **Усилие: S.** Реестр + i18n-копия уже есть; нужна страница-список + маршрут.
  Пара к двуязычному `Glossary` (этот тик) и risk-disclosure.

### Идея: CI-гард паритета локалей (каждый ключ есть и в ru, и в en)
Двуязычность растёт, но ничто не ловит «добавил ключ в ru.json, забыл en.json» —
EN-инвестор молча увидит сырой ключ или русский фолбэк. Гард в CI: множества
ключей `ru.json` и `en.json` совпадают (с whitelist намеренных исключений), и
отдельно — у каждого `GLOSSARY_TERMS` есть `term`+`definition` в обоих языках.
- **Ценность:** не даёт i18n-долгу расти молча — перевод остаётся ПОЛНЫМ, а не
  наполовину; дополняет ratchet кириллицы (тот ловит хардкод-RU, этот — дыры в EN).
- **Монетизация:** не прямая — качество демо для иностранного партнёра.
- **Усилие: S.** Скрипт сравнения двух JSON по плоским ключам + список исключений;
  в `lint:all` рядом с check-no-cyrillic.

### Идея: Двуязычные уведомления (язык пользователя, а не только UI-строки)
Перевели UI-строки и глоссарий, но текст уведомлений рождается на бэкенде и,
скорее всего, только по-русски — EN-инвестор в EN-интерфейсе всё равно получит
русские «Своп исполнен»/«Комиссии начислены». Храним язык пользователя и рендерим
тело уведомления по шаблону на его языке (ключ+параметры, а не готовая строка).
- **Ценность:** перевод становится сквозным, а не «только то, что на экране» —
  уведомления это половина продукта; критично для серьёзного EN-демо.
- **Монетизация:** не прямая — целостность UX для иностранной аудитории.
- **Усилие: M.** Поле языка у юзера (есть `dlmm.user.language` на фронте — поднять
  в профиль) + шаблоны уведомлений ключ→{ru,en} в notification-service; не трогать
  денежный путь. Пара к locale-aware форматированию чисел/дат.

### Идея: Алерт «CB-fallback срабатывает на 100% вызовов» (молчаливо мёртвая фича)
AML-скан был мёртв ДОЛГО: downstream-вызов падал на каждом запросе, CB-fallback
тихо возвращал пустой список — фича «здорова», но не работает. Гард/алерт: если
fallback какого-то клиента срабатывает в ~100% случаев за окно — это не
транзиентный сбой, а перманентно сломанный путь; поднимать алерт, а не глотать.
- **Ценность:** ловит целый класс «деградировали в no-op и не заметили» —
  особенно опасный для комплаенс/денежных путей, которые «не падают».
- **Монетизация:** не прямая — надёжность/доверие; меньше инцидентов на проде.
- **Усилие: S–M.** Resilience4j уже считает метрики fallback; порог + алерт в
  Prometheus/healthcheck. Дополняет CI-гард контракта (тот — до прода, этот — на проде).

### 🟡 Идея: Тип транзакции и категория флага в AML-ответе — txType реализован 2026-06-17, category открыта
`SuspiciousTransactionResponse` не несёт тип операции (колонка «Тип» в админке
пустая) и не различает КАТЕГОРИЮ флага (частота / TVL / импакт). Добавляем
`txType` и `category`, красим бейджем по категории.
- **Ценность:** офицер сразу видит «что за операция и почему флаг» без чтения
  длинной reason-строки; основа для фильтра по категории и метрик.
- **Монетизация:** risk/compliance-модуль (ENTERPRISE-отчётность).
- **Усилие: S.** `txType` уже есть в источнике (читаем рядом с amountIn);
  category — enum по сработавшему детектору. Пара к диспозиции при «Просмотрено».

### Идея: Real-time AML — флаг на событии свопа, а не 15-мин скан
Сейчас подозрительное ищется периодически (BFF-скан по запросу + 15-мин

### Идея: Демо-флаги AML — чтобы страница «подозрительных» не была пустой

  иначе фича выглядит мёртвой; теперь к ней есть и CSV-выгрузка (этот тик).
- **Монетизация:** часть risk/compliance-модуля (ENTERPRISE).

### Идея: Диспозиция при «Просмотрено» (false-positive / эскалация / закрыто)
Кнопка «Просмотрено» сейчас лишь штампует reviewedAt/By — без ПРИЧИНЫ. Добавляем

### ✅ Идея: «Эффективная комиссия пула» из реальных свопов — реализовано 2026-06-17 (fee-stats эндпоинт + строка в шапке пула)
fee_rate (bps) теперь пишется по каждому свопу. Считаем по пулу СРЕДНЮЮ

- **Ценность:** «заявленная 0.30% vs фактическая 0.42%» — честная экономика пула

### Идея: Альтернатива — хранить fee_rate как ratio с расширенной точностью (схема)

- **Монетизация:** не прямая — техдолг/консистентность.

### Идея: Локаль-aware форматирование чисел/дат/валют везде (не точечно)

### Идея: «Безопасная сумма» при высоком влиянии на цену (уменьшить в один тап)
Свежий гейт высокого влияния (≥5%) блокирует своп до подтверждения — но не
помогает решить проблему. Рядом с предупреждением — кнопка «уменьшить до суммы с
влиянием <1%»: бинарным поиском по котировке находим максимальный amountIn,
дающий приемлемое влияние, и подставляем его.
- **Ценность:** превращает «стоп, опасно» в «вот безопасный размер» — пользователь

что цена выйдет за границы позиции в ближайшие 24ч, и помечаем «край» —
«высокий риск выхода из диапазона при текущей волатильности».
- **Ценность:** опережающий сигнал (центрируй/расширь диапазон заранее) — для
  активных LP это разница между «реагирую на убыток» и «избегаю его»; уникальный
  риск-слой, которого нет у пассивных AMM-витрин.
- **Монетизация:** премиум риск-радар; вход в авто-стратегии «держать в диапазоне».
- **Усилие: M.** Волатильность уже аккумулируется на пул; нужно сопоставить σ с
  расстоянием активного бина до границ позиции (в бинах) и откалибровать порог.
  Отличается от алерта-выхода (реактивный, постфактум) — этот срабатывает заранее.

- **Монетизация:** copy-fee / доля от результата ведущему LP + платформе.
- **Усилие: M.** Realized-APY и per-bin данные есть; нужны рейтинг, согласие на
  публичность портфеля и движок «зеркалирования» добавления ликвидности.

### Идея: Авто-налоговый отчёт LP для РФ
Автогенерация годового отчёта о доходах LP (забранные комиссии, P&L) в формате,
удобном для декларации в РФ — реальная боль инвестора в крипто/DeFi.
- **Ценность:** закрывает болезненный комплаенс-сценарий, дифференциатор для
  серьёзных инвесторов; повод вернуться на платформу раз в год минимум.
- **Монетизация:** премиум-фича / плата за отчёт; апсейл к ENTERPRISE-тарифу.
- **Усилие: M.** Данные уже в `transactions` / `fee_accruals` (claimed-история);
  нужен агрегатор по налоговому периоду + экспорт в нужную форму.

### Идея: «Стейкинг витрины» — программируемые маркетинговые пулы
Партнёрские пулы с временным бустом APY, которые бренды/эмитенты токенов
оплачивают как рекламу размещения ликвидности (спонсируемый farming поверх
существующего reward-движка `12-seed-farming-rewards`).
- **Ценность:** эмитенту — гарантированная глубина рынка его актива; LP — буст
  доходности; платформе — новый B2B-канал выручки без изменения core-механики.
- **Монетизация:** размещение (listing fee) + комиссия с бюджета буста.
- **Усилие: S–M.** Farming-конфиги уже есть; нужен админ-флоу «спонсируемый пул»
  + бейдж в каталоге и срок действия буста.

### Идея: Демо-песочница инвестора с виртуальным портфелем
Публичный режим «попробуй без денег»: виртуальный SRUB-баланс, реальный движок
свопов/ликвидности на изолированных пулах, лидерборд доходности за неделю.
- **Ценность:** низкобарьерная воронка (демо уже умеет всё нужное — это
  продуктизация текущего демо-стека); обучение через практику; лиды в KYC.
- **Монетизация:** конверсия в боевые счета; спонсорство конкурсов недели.
- **Усилие: M.** Изоляция org/балансов уже есть (orgId, internal credit);
  нужен авто-онбординг без KYC с лимитами и сброс песочницы по расписанию.

### Идея: RWA-пулы — от SGOLD к облигациям и недвижимости
Расширить линейку реальных активов (SGOLD уже торгуется) токенизированными
корп. облигациями Сбера и паями недвижимости с ликвидностью через DLMM-бины.
- **Ценность:** «биржа реальных активов» с узким спредом — уникальное РФ-предложение;
  консервативному инвестору понятнее крипты; синергия с казначейскими волтами.
- **Монетизация:** комиссия эмиссии/листинга RWA + спред пулов + кастоди.
- **Усилие: L** (юр. обвязка), технически S — каталог токенов и движок уже
  поддерживают любой FIAT_BACKED/RWA-актив.

### Идея: Мерчант-эквайринг поверх пулов (СБП-мост)
Приём оплаты в стейблах (SUSDT и др.) с мгновенной конвертацией в SRUB по
пулу и выплатой мерчанту: «крипто-эквайринг без волатильности».
- **Ценность:** мерчанту — новый платёжный канал с гарантированным курсом
  исполнения (концентрированная ликвидность = предсказуемый слиппедж);
  платформе — стабильный своп-объём (комиссии LP растут).
- **Монетизация:** эквайринговая комиссия + спред; подписка за rate-lock окна.
- **Усилие: M.** Движок свопов готов; нужен merchant-API (инвойс → квота →
  исполнение → вебхук) и связка выплат с СБП.

### Идея: Структурные транши LP (senior/junior)
Разделить пул-позицию на два класса: senior (фикс-доходность, защита от IL за
счёт junior) и junior (плечо на комиссии + остаточный IL-риск).
- **Ценность:** один продукт покрывает два профиля инвестора — «как депозит,
  но выше ставка» и «агрессивный доход»; классика структурных продуктов,
  знакомая банковской рознице.
- **Монетизация:** структуризационная комиссия + performance fee junior-транша.
- **Усилие: L.** Нужен волт-агрегатор с водопадом выплат; per-bin учёт комиссий
  уже даёт точную базу распределения. Пилот на 1 пуле.

### Идея: «Семейный портфель» — мульти-доступ к LP с ролями
Совместное управление позициями для семьи/малых команд: владелец делится
view-only или trade-доступом (orgId/orgRole в JWT уже есть), лимиты на члена.
- **Ценность:** удержание через сетевой эффект домохозяйства; безопасный
  «детский» режим как обучение инвестициям; B2C-аналог корпоративных команд.
- **Монетизация:** семейная подписка (фикс/мес) + апсейл лимитов.
- **Усилие: S–M.** Org-модель и TeamPage уже есть — нужен B2C-онбординг
  «пригласить родственника» + пресеты ролей/лимитов.

### Идея: Голосовой/чат-ассистент инвестора (Сберкот + GigaChat)
Диалоговый слой поверх платформы: «сколько я заработал за неделю?», «переложи
половину SUSDT-позиции в SGOLD», «почему упал APY?» — с подтверждением операций.
- **Ценность:** радикально снижает порог для нетехнической аудитории; Сберкот
  уже маскот-гид — логичная эволюция в полноценного ассистента экосистемы.
- **Монетизация:** премиум-фича PRO-тарифа; рост конверсии в операции.
- **Усилие: M–L.** Все данные доступны по внутренним API; нужен NLU-слой
  (GigaChat), маппинг намерений на API и жёсткие подтверждения для money-операций.

### Идея: Мост в СберИнвестиции — кросс-селл из брокерки
Покупка платформенных активов (SETH, SGOLD, LP-волты) прямо из приложения
СберИнвестиции как «альтернативные инструменты»; единый портфельный вид.
- **Ценность:** мгновенный доступ к многомиллионной брокерской аудитории без
  собственного привлечения; знакомый интерфейс снижает порог.
- **Монетизация:** комиссия дистрибуции с брокерки + рост TVL/объёмов.
- **Усилие: L** (интеграционные согласования), технически M — API уже
  self-describing, нужен B2B-контракт счетов и SSO-мост.

### Идея: Подарочные SRUB-сертификаты (gift-ссылки)
Отправка SRUB/позиции по ссылке/QR: получатель проходит лёгкий онбординг и
получает токены — «подари другу первый вклад в ликвидность».
- **Ценность:** виральная петля привлечения с нулевым CAC; естественный повод
  для первого касания DeFi-продукта.
- **Монетизация:** breakage неактивированных подарков + конверсия получателей
  в активных LP; брендированные корпоративные подарки (B2B2C).
- **Усилие: S–M.** Internal credit/deduct уже есть; нужен escrow-токен ссылки,
  TTL и анти-фрод лимиты.

### Идея: Данные как продукт — исторический маркет-дата фид
Продажа очищенных исторических данных (OHLCV, объёмы, глубина бинов,
agg-метрики ликвидности) исследователям, вузам и квантам — отдельно от
trading-API: бакеты выгрузок + витрина в ClickHouse.
- **Ценность:** RWA/DLMM-данные РФ-рынка уникальны; академия и фонды платят за
  чистые ряды; усиливает бренд «инфраструктурного провайдера».
- **Монетизация:** подписка на фид/выгрузки, тарифы по глубине истории.
- **Усилие: S–M.** ClickHouse уже копит аналитику; нужен экспорт-слой
  (S3/parquet) и биллинг доступа.

### Идея: AML/комплаенс-движок как отдельный продукт
Детекторы паттернов (fast-in-fast-out, round-amount repeats, TVL-аномалии) уже
работают в transaction-service — упаковать их в standalone-API «комплаенс для
финтехов» с вебхуками алертов и отчётами для регулятора.
- **Ценность:** РФ-финтехам нужен готовый транзакционный мониторинг (115-ФЗ);
  у Сбера — доверие бренда + реальные данные для тюнинга правил.
- **Монетизация:** подписка по объёму транзакций + плата за кастомные правила.
- **Усилие: M.** Ядро есть; нужен мультитенантный ingest-API, изоляция данных
  и конструктор правил.

### Идея: Telegram-боты поверх платформенного API
Официальный TG-бот (баланс, котировки, алерты, простые свопы с подтверждением)
+ программа для сторонних ботов через публичный API с ревью.
- **Ценность:** TG — главный канал РФ-крипто-аудитории; ноль-friction доступ
  без установки приложения; алерты возвращают пользователей.
- **Монетизация:** конверсия в полные аккаунты; комиссия с бот-свопов;
  партнёрский revenue-share для сторонних ботов.
- **Усилие: S–M.** API self-describing и нотификации готовы; нужен бот-слой
  (webhook, привязка аккаунта через deep-link) и лимиты на бот-операции.

### Идея: Авто-компаундинг комиссий (реинвест в позицию)
Опция «реинвестировать»: забранные комиссии автоматически добавляются обратно
в ту же LP-позицию (сложный процент) вместо зачисления на баланс.
- **Ценность:** «проценты на проценты» — понятный банковской рознице механизм;
  заметно красивее кривая доходности в портфеле; выше удержание TVL.
- **Монетизация:** небольшая комиссия с авто-реинвеста; апсейл к PRO.
- **Усилие: S–M.** Auto-claim планировщик и addLiquidity уже есть — нужен
  флаг политики «куда направлять» и атомарный claim→add путь.

### Идея: «Миссии ликвидности» — квесты с наградами
Геймифицированные задания (первый своп, неделя в позиции, 3 пула, забор
комиссий) с бейджами Сберкота и буст-наградами фарминга.
- **Ценность:** направляет новичка по золотому пути продукта; +activation,
  +retention; повод для пушей возврата.
- **Монетизация:** косвенная (рост активов/объёмов); спонсируемые миссии
  от партнёров-эмитентов.
- **Усилие: S–M.** События уже в Kafka — нужен счётчик прогресса, каталог
  миссий и выдача наград через farming-движок.

### Идея: Private-banking уровень — персональный LP-консьерж
Для крупных клиентов: персональный менеджер, индивидуальная стратегия
диапазонов, отчётность «как в банке», приоритетная линия и закрытые пулы.
- **Ценность:** переносит знакомую модель private banking в DeFi; снимает
  страх самообслуживания у капитала 10M₽+; высокая LTV.
- **Монетизация:** management fee по AUM-сетке + закрытые продукты.
- **Усилие: M** (процессы/люди больше, чем код): роли и закрытые пулы
  частично есть (orgId, статусы пулов), нужен консьерж-кабинет менеджера.

### Идея: Еженедельный AI-дайджест портфеля от Сберкота
Автоматическое письмо/пуш раз в неделю: доходность позиций, забранные
комиссии, IL, события пулов и 1–2 персональные рекомендации (LLM-генерация
по данным портфеля).
- **Ценность:** возвращает пассивных пользователей; «личный аналитик» без
  усилий; повышает доверие прозрачностью.
- **Монетизация:** удержание/реактивация TVL; расширенный дайджест в PRO.
- **Усилие: S–M.** Все данные в API; нужен планировщик-генератор + шаблоны
  и канал доставки (email/пуш уже есть в notification-service).

### Идея: Встраиваемый своп-виджет (embeddable iframe/SDK)
Виджет «обменять» для партнёрских сайтов и медиа (финпорталы, кошельки):
3 строки кода — и у партнёра свой обменник на ликвидности платформы.
- **Ценность:** дистрибуция без своего трафика; партнёр получает функцию,
  платформа — объём и новых пользователей (deep-link онбординг).
- **Монетизация:** revenue-share комиссии со свопов виджета; брендирование.
- **Усилие: M.** Своп-API готов; нужен изолированный виджет-бандл, partner-key
  c referrer-атрибуцией и лимитами.

### Идея: RFQ-доска для крупных сделок (P2P-OTC с эскроу)
Заявочная доска «куплю/продам объёмом» для тикетов, которым дорог слиппедж
пулов: пользователи публикуют RFQ, контрагенты откликаются, расчёт — через
платформенный эскроу (OTC-тип уже есть в transaction-service).
- **Ценность:** удерживает крупные сделки внутри платформы (сейчас ушли бы на
  внебиржу); пулам — меньше токсичного потока, юзерам — лучшая цена.
- **Монетизация:** комиссия с матчинга + плата за приватные RFQ.
- **Усилие: M.** Леджер/эскроу-механика есть; нужен матчинг-сервис заявок и
  UI-доска с откликами.

### Идея: «Календарь доходности» — выплаты как купоны
Прогнозный календарь: ожидаемые комиссии по позициям и farming-награды,
разложенные по неделям/месяцам, как купонный календарь облигаций.
- **Ценность:** переводит DeFi-доходность на язык, знакомый владельцу ОФЗ;
  планирование кэшфлоу = аргумент для консервативного инвестора.
- **Монетизация:** удержание; экспорт в iCal/брокерские отчёты — PRO-фича.
- **Усилие: S–M.** Realized-история и APY есть; нужен прогнозный разложитель
  и календарный виджет на дашборде.

### Идея: «Чек здоровья пула» — прозрачный аудит-бейдж
Публичный автоматический бейдж на каждом пуле: инварианты (композиция бинов,
liquidity=value, свежесть свечей) проверяются непрерывно, статус виден
инвестору («Проверено: 12.06, 14:00»).
- **Ценность:** доверие через прозрачность — то, чего нет у анонимных DEX;
  превращает внутренние self-check'и сидов в продуктовую фичу.
- **Монетизация:** косвенная (конверсия осторожных), API статусов — в
  data-продукт.
- **Усилие: S.** Инвариант-проверки уже написаны (sql self-checks) — нужен
  переодический job + поле статуса в pools API + бейдж в UI.

### Идея: Симулятор «что если» для позиции
Интерактивный слайдер на странице пула: «если цена уйдёт на ±X% — сколько
комиссий заработаю vs IL потеряю» с графиком (по реальной bin-математике).
- **Ценность:** главный страх LP — непонимание IL; симулятор делает риск
  ощутимым ДО депозита; образовательный эффект + конверсия.
- **Монетизация:** конверсия в депозиты; расширенные сценарии (волатильность,
  объёмы) — PRO.
- **Усилие: M.** BinMath на фронте частично есть (binPriceRange); нужен
  расчётный модуль сценариев + виджет.

### Идея: Авто-вывод комиссий на карту/счёт (fiat off-ramp)
Опция «выводить заработанные комиссии на карту Сбера ежемесячно»: claim →
конвертация в SRUB (quote-only уже есть) → выплата на счёт.
- **Ценность:** замыкает цикл «инвестировал → получаю живые деньги» — главный
  аргумент для консервативного инвестора; ощущение «дивидендов».
- **Монетизация:** комиссия за вывод; план «без комиссии» в PRO.
- **Усилие: M–L** (интеграция выплат), технически quote-only claim и
  планировщик авто-claim уже готовы.

### Идея: Бенчмарк-страница «vs депозит» 
Публичный лендинг-калькулятор: «1 млн ₽ на год: вклад X% vs LP-портфель
(история реальных комиссий платформы)» с честным разбросом и рисками.
- **Ценность:** конверсия холодного трафика через знакомое сравнение;
  прозрачность реальных данных (не обещания) = доверие.
- **Монетизация:** acquisition; SEO-трафик по запросам «куда вложить».
- **Усилие: S.** История комиссий/APY есть; нужна одна страница + методология.

### Идея: Лимитки-как-сбережение: «куплю просадку» автопланы
Шаблоны лимитных ордеров для розницы: «покупать SETH каждый раз при −5% от
текущей цены, бюджетом N₽/мес» — эскроу-механика лимиток уже работает.
- **Ценность:** превращает страх волатильности в стратегию («куплю дешевле»);
  знакомый паттерн отложенного ордера из брокерок, но автоповторяемый.
- **Монетизация:** комиссия исполнения; PRO-шаблоны (ступени, трейлинг).
- **Усилие: S–M.** Эскроу/исполнение лимиток есть (проверено вживую);
  нужен планировщик-генератор ордеров + 3 пресета в UI.

### Идея: Корпоративные «зарплатные» LP-программы
Работодатель (начиная со Сбера) докидывает % к взносу сотрудника в выбранные
консервативные пулы (мэтчинг 1:1 до лимита) — как корпоративная пенсия, но
ликвидная.
- **Ценность:** B2B2C-канал с нулевым CAC; лояльность сотрудников; большие
  стабильные TVL-притоки.
- **Монетизация:** management fee с корпоративного пула мэтчинга.
- **Усилие: M.** Org-роли и internal credit есть; нужен договор-флоу
  работодателя и отчётность по программе.

### Идея: Лента активности пула в реальном времени (social proof)
Живой тикер на странице пула и в каталоге: «5 мин назад: своп 60 тыс ₽»,
«час назад: +ликвидность 120 тыс ₽» — обезличенно, из готовых Kafka-событий.
- **Ценность:** «здесь живые деньги» — главный social-proof для нового
  инвестора; повышает доверие и FOMO-конверсию в депозит.
- **Монетизация:** косвенная (конверсия); виджет-тикер в партнёрские медиа.
- **Усилие: S.** События уже летят (pool-events); нужен буфер последних N
  + websocket/поллинг и строка-тикер в UI.

### Идея: «Сберкот-радар» — еженедельный рейтинг пулов
Авто-подборка «3 пула недели» по живым метрикам (оборот, APY-стабильность,
приток LP) с бейджем в каталоге и пушем подписчикам.
- **Ценность:** снимает паралич выбора новичка; направляет ликвидность в
  здоровые пулы; регулярный повод вернуться.
- **Монетизация:** премиум-размещение для эмитентов (прозрачно помеченное).
- **Усилие: S–M.** Метрики уже считаются; нужен скоринг-джоб + бейдж + пуш.

### Идея: «Пульс портфеля» — нотификации об изменении стоимости
Подписка на дельту портфеля: «за день +1,2% (+74 тыс ₽)» утренним пушем и
порог-алерты («если просадка >3% — сообщить сразу»), на базе уже живых
PoolPriceSync-фидов и нотификаций.
- **Ценность:** ежедневная точка контакта без открытия приложения; контроль
  без тревожности (агрегат, не тики).
- **Монетизация:** retention; тонкие настройки порогов — PRO.
- **Усилие: S.** Цены и нотификации есть; нужен дневной снапшот портфеля
  и шаблон дайджест-пуша.

### Идея: Партнёрская витрина структурных нот на LP-доходности
Упаковка LP-доходности в «ноту» с фиксированными датами и условиями для
дистрибуции через премьер-менеджеров банка (бумага поверх волтов).
- **Ценность:** канал в существующую сеть продаж банка; знакомый формат
  для клиента private/премьер; масштабируемый AUM.
- **Монетизация:** структуризационная комиссия + дистрибуционный спред.
- **Усилие: L** (юр/продукт), технически M — волты+отчётность.

### Идея: PWA-установка с виджетом портфеля
Прогрессивное веб-приложение: установка на домашний экран, оффлайн-обложка,
виджет «портфель сегодня» (iOS/Android) с дельтой за день.
- **Ценность:** иконка на телефоне = ежедневное касание без сторов и
  модерации; виджет возвращает в приложение.
- **Монетизация:** retention/частота сессий; нативный шорткат к свопу.
- **Усилие: S–M.** Vite-PWA-плагин + манифест + service worker; мобильная
  вёрстка уже верифицирована (0 оверфлоу, тёмная тема ок).

### Идея: QR-handoff сессии «с десктопа в руку»
Кнопка «Продолжить на телефоне»: QR с одноразовым коротким токеном —
открывает ту же страницу залогиненным на мобильном.
- **Ценность:** демо-вау и реальный кейс (начал на работе — закончил в метро);
  снижает трение мобильного входа без пароля.
- **Монетизация:** конверсия мобильных сессий; основа для биометрии позже.
- **Усилие: M.** Короткоживущий one-time токен + QR-рендер; refresh-механика
  уже есть, нужен exchange-эндпоинт с жёстким TTL.

### Идея: Админ-консоль как продукт «Оператор площадки»
Упаковать admin-ui (пользователи/KYC, пулы, AML-разбор, OTC desk, когорты)
в роль-базированную консоль для white-label-партнёров (идея white-label уже
в бэклоге — это её операционная половина).
- **Ценность:** партнёру нужен не только движок, но и готовый бэк-офис;
  сокращает time-to-launch площадки с месяцев до недель.
- **Монетизация:** входит в лицензию white-label + плата за доп. роли/SLA.
- **Усилие: M.** Консоль уже работает (проверена вживую); нужны
  мультитенантные фильтры и матрица прав.

### Идея: Алерты аномалий для оператора (admin-ops)
Push/Telegram оператору при: остановке роста свечей, дрейфе инвариантов,
росте 5xx, расхождении TVL-роллапа — то, что loop ловил вручную, как продукт.
- **Ценность:** инциденты замечаются до жалоб клиентов; меньше дежурного
  ручного мониторинга.
- **Монетизация:** в составе Enterprise-SLA; экономия на поддержке.
- **Усилие: S–M.** Метрики уже в Prometheus/Grafana; нужен alert-router в
  notification-service + 5–6 готовых правил.

### Идея: Единый «словарь метрик» платформы (metrics contract)
Зафиксировать словарь бизнес-метрик (объём = SRUB-нога, TVL = сумма резервов,
APY = методика) одним документом + библиотечной функцией на бэке и фронте —
loop трижды чинил один и тот же класс расхождений в разных местах.
- **Ценность:** инвестору и аудитору везде показывают ОДНО и то же число;
  меньше регрессий копи/единиц; быстрее онбординг разработчиков.
- **Монетизация:** косвенная — доверие/аудит; обязательное условие white-label.
- **Усилие: S.** Документ + вынос расчётов в dlmm-common/format-хелперы,
  постепенная миграция экранов.

### Идея: Режим «Демо-сценарист» для пресейла
Кнопка для продавца: разогнать показ — серия заготовленных живых свопов/
добавлений с паузами и подсветкой того, что меняется (объём, свечи, комиссии).
- **Ценность:** идеальное демо без ручного ввода; повторяемость на встречах;
  каждый показ генерирует настоящие данные (наш smoke-конвейер — как фича).
- **Монетизация:** инструмент продаж; ускоряет цикл сделки.
- **Усилие: S–M.** Все вызовы готовы (скрипт smoke = прототип); нужен
  оркестратор сценария + оверлей-подсказки в UI.

### Идея: SLA-витрина аптайма для институционалов
Публичная страница статуса (аптайм сервисов, p95 латентности, история
инцидентов) + приватный SLA-отчёт для корпоративных клиентов — то, что
требует любой казначей перед заводом денег.
- **Ценность:** снимает возражение «а это вообще надёжно?»; обязательный
  атрибут B2B-продаж институционалам; дифференциатор vs анонимные DEX.
- **Монетизация:** входит в Enterprise-SLA; повышает конверсию крупных тикетов.
- **Усилие: S–M.** Health/actuator + Prometheus уже есть; нужен сборщик
  аптайма (внешний пробер) + статус-страница + шаблон отчёта.

### Идея: Песочница на тестовых деньгах (paper-trading)
Режим «демо-счёт»: виртуальный баланс, те же пулы и математика, но без
реальных средств — обучение свопам/LP/комиссиям без риска, с переходом на
боевой счёт в один клик.
- **Ценность:** убирает страх первого касания DeFi у массового РФ-инвестора;
  обучающая воронка; безопасная площадка для контента/вебинаров.
- **Монетизация:** конверсия paper→боевой; обучающий контент как лид-магнит.
- **Усилие: M.** Движок и UI готовы; нужен изолированный «виртуальный» тип
  счёта в token-service (флаг + отдельный кошелёк) и баннер режима.

### Идея: «Спящая ликвидность» — авто-подсказка по пулам с низким APY
Пулы-гиганты с почти нулевым APY (как SBTC 0.01% — много TVL, мало объёма)
детектировать и подсказывать LP: «здесь капитал простаивает — переложите в
пул X с APY N%», прямо на витрине/в дайджесте.
- **Ценность:** повышает реальную доходность LP (меньше мёртвого капитала),
  growth-метрика «активный TVL»; честная забота вместо обмана «0.0%».
- **Монетизация:** удержание + рост оборота (перелив в активные пулы = больше
  комиссий платформе).
- **Усилие: S–M.** APY/объём уже считаются; нужен детектор «idle-пула» +
  ранжирование альтернатив + копирайт подсказки.

### Идея: Бейдж «глубина рынка» на карточке пула
Простой индикатор для новичка: «крупную сделку (1 млн ₽) пул проведёт со
слиппеджем ~X%» — превью из bin-резервов, без раскрытия механики бинов.
- **Ценность:** переводит «концентрированную ликвидность» на язык понятной
  выгоды (мало проскальзывания); помогает выбрать пул осознанно.
- **Монетизация:** конверсия в свопы/депозиты; апсейл аналитики в PRO.
- **Усилие: S.** Симуляция свопа уже есть (quote-эндпоинт); нужен фоновый
  расчёт на фикс-сумму + бейдж.

### Идея: Калькулятор доходности «vs вклад» (развитие)
К уже реализованному калькулятору доходности на странице пула добавить
сравнение с банковским вкладом: тянуть ключевую ставку ЦБ (price-oracle уже
ходит в ЦБ РФ) и показывать «LP ≈ N ₽ vs вклад под X% ≈ M ₽».
- **Ценность:** прямое сравнение с понятным якорем = сильнейший конверсионный
  аргумент для консервативного РФ-инвестора.
- **Монетизация:** конверсия в депозиты; «обогнали вклад» — маркетинг-хук.
- **Усилие: S.** Калькулятор и oracle-фид ЦБ готовы; нужна ставка вклада в API
  oracle + одна строка сравнения в компоненте.

### Идея: Реалистичный прогноз по истории объёма (а не текущему APY)
Вместо линейной экстраполяции текущего APY — прогноз по медиане комиссий за
N последних дней (из fee_accruals/ohlcv), с диапазоном «пессимистично…
оптимистично».
- **Ценность:** честнее и устойчивее к скачкам APY; снимает претензию
  «обещали, не сбылось»; доверие.
- **Монетизация:** удержание; премиум-горизонты прогноза в PRO.
- **Усилие: M.** История объёмов/комиссий есть; нужен агрегат-эндпоинт
  (медиана/перцентили) + замена формулы в калькуляторе.

### Идея: Происхождение оценки APY — бейдж «по факту 24ч» vs «по модели»
Оценка APY теперь либо выводится из реального объёма за 24ч, либо подпирается
модельным полом по тарифу комиссии (когда живого объёма мало). Показывать
пользователю, какая ветка сработала: маленький бейдж/тултип «по факту за 24ч»
против «оценка по модели».
- **Ценность:** честность и доверие; снимает риск претензии «APY завышен»;
  обучает, что APY — это оценка, а не обещание.
- **Монетизация:** доверие → удержание; в PRO — раскрытие методики и история APY.
- **Усилие: S.** Бэкенд уже различает обе ветки в `estimateApyPercent`; добавить
  поле `apySource: LIVE|MODEL` в `PoolResponse` + бейдж на карточке/детали пула.

### Идея: «Эффективная ставка» позиции — реальный реализованный APY
На странице позиций показывать по каждой позиции фактический APY =
(забранные + накопленные комиссии) / депозит / возраст, в годовых — «ваша
позиция реально приносит X%», рядом с оценочным APY пула.
- **Ценность:** переводит абстрактный APY пула в «мои деньги»; самый честный
  показатель доходности; сильный аргумент удержания и доверия.
- **Монетизация:** удержание; в PRO — график реализованного APY во времени и
  выгрузка для налогового отчёта.
- **Усилие: M.** Данные есть (единый источник комиссий per-bin owed,
  `initial_deposit`, `created_at`); нужен расчёт realized-APY в getUserPositions
  + колонка/карточка в UI.

### Идея: Фильтр пулов «только с реальной доходностью» (LIVE-only)
Раз у APY появилось происхождение (LIVE vs MODEL), дать в списке/сравнении
пулов чип-фильтр «только с реальным объёмом» — скрыть модельные оценки и
оставить пулы, чей APY подтверждён фактической торговлей за 24ч.
- **Ценность:** PRO- и институциональные инвесторы хотят реальные, а не
  модельные числа; прозрачность площадки.
- **Монетизация:** PRO-фильтр; аргумент для институционального сегмента.
- **Усилие: S.** Тот же флаг `apySource` (идея выше) + фильтр-чип и предикат
  сортировки на `PoolsPage`/`PoolComparePage`.

### Идея: Сохранённые фильтры-отчёты («Мои выгрузки»)
На странице транзакций дать сохранять комбинацию фильтров (тип + статус +
диапазон дат) под именем и переоткрывать одним кликом — для регулярной
отчётности (например, «свопы за месяц»). Теперь, когда фильтры реально
работают на бэке (type/from/to через Specification), это надстройка над ними.
- **Ценность:** экономит рутину бухгалтеру/инвестору; «отчётность в один клик».
- **Монетизация:** удержание; в PRO — общий доступ к сохранённым отчётам в команде.
- **Усилие: S.** Чисто фронт: localStorage-стор (как `positionAlertsStore`) +
  выпадающий список «Мои выгрузки» рядом с фильтрами; экспорт уже есть.

### Идея: Серверный потоковый экспорт больших историй
CSV-экспорт сейчас клиентский, с потолком 5000 строк. Для институционалов с
длинной историей — серверный стриминговый эндпоинт `/transactions/me/export`
(CSV/XLSX) поверх той же Specification-фильтрации, отдающий весь срез потоком.
- **Ценность:** снимает потолок; XLSX-формат привычнее для финслужб.
- **Монетизация:** ENTERPRISE-фича; основа для подписи/штампа отчёта.
- **Усилие: M.** Эндпоинт со `StreamingResponseBody` + переиспользовать
  Specification из `getUserTransactions`; на фронте — переключатель «весь срез».

### Идея: Годовой налоговый отчёт (3-НДФЛ-ready)
Свести по году реализованный P&L и уплаченные/полученные комиссии в разрезе
токенов в форму, пригодную для декларации РФ-инвестора. Источник — те же
транзакции + история комиссий (`fee_accruals`).
- **Ценность:** снимает главную боль РФ-инвестора (налоговая отчётность);
  сильный аргумент доверия и удержания на годовом горизонте.
- **Монетизация:** PRO/ENTERPRISE; партнёрство с налоговыми сервисами.
- **Усилие: L.** Нужен агрегат realized-P&L по FIFO/средней + сводка комиссий +
  форматтер отчёта; считать на бэке, выгрузка PDF/XLSX.

### Идея: Авто-сплит крупной сделки (TWAP-lite)
Когда влияние на цену заметно (квота вернула высокий priceImpact), предложить
разбить сделку на N частей и исполнить последовательно — суммарно меньше
проскальзывания, чем один большой своп. Кнопка «Исполнить в N частей».
- **Ценность:** прямая экономия для крупного ордера; «умное исполнение» как у
  топовых DEX/брокеров — аргумент для активного трейдера.
- **Монетизация:** PRO-фича; основа для лимитной/алго-витрины.
- **Усилие: M.** priceImpact уже в квоте; нужен сплиттер (N пере-квот +
  последовательный executeSwap с общим idempotency-префиксом) и индикатор прогресса.

### Идея: Мягкая подсказка Сберкота о крупной сделке (Simple)
В Simple демо-пулы глубокие — влияние редко превышает доли процента, так что
жёсткий порог-предупреждение (5%) не срабатывает. Вместо него — дружелюбная
подсказка Сберкота, когда impact выше «типичного для пула» (например, p90 по
истории или просто >0.3%): «Крупная сделка чуть двигает цену — это нормально».
- **Ценность:** обучает новичка без алармизма; повышает доверие к цифрам.
- **Монетизация:** вовлечённость/удержание; обучающий онбординг.
- **Усилие: S.** Порог от типичного impact пула + один тост/баббл Сберкота на
  странице Simple-свопа.

### Идея: Подсказка «глубины» на форме свопа — до какой суммы цена почти не двигается
Ещё до ввода суммы показывать на свопе ориентир «до ≈ N ₽ влияние < 0.5%» —
оценка по ликвидности активного диапазона бинов. Помогает выбрать размер сделки.
- **Ценность:** проактивно (в отличие от бейджа глубины на карточке пула —
  здесь это рекомендация размера прямо в форме); снижает «сюрприз» по impact.
- **Монетизация:** удержание; PRO — точная кривая impact(сумма).
- **Усилие: M.** Нужен endpoint/расчёт «макс. сумма при заданном impact» из
  reserves активных бинов (бинарный поиск по той же swap-математике).

### Идея: Комплаенс-экспорт админ-фида транзакций
Раз у админ-фида транзакций заработали фильтры тип+статус+даты — дать админу
выгрузку отфильтрованного среза (CSV/XLSX) с колонками для комплаенса: юзер,
AML-флаг, reviewedBy/reviewedAt, сумма в SRUB. Отдельно от пользовательского
экспорта (там нет чужих юзеров/ревью).
- **Ценность:** регуляторная отчётность и расследования в один клик — must-have
  для финплощадки под надзором ЦБ.
- **Монетизация:** часть ENTERPRISE/комплаенс-тарифа площадки-оператора.
