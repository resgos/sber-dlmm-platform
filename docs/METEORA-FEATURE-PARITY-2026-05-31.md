## 1. DLMM — ядро

| Фича Meteora | Статус | Комментарий |
|---|---|---|
| Дискретные ценовые бины + один активный бин (0 проскальзывания) | ✅ | `BinMath`, инвариант F-12 `reserveX·price + reserveY = liquidity` |
| Концентрированная ликвидность | ✅ | |
| Шаг бина / fee-tiers | ✅ | Бейджи fee/bin-step на карточках пулов |
| Базовая комиссия | ✅ | `FeeCalculator` |
| Переменная (динамическая) комиссия от волатильности | 🟡 | Формула есть (`totalFeeBps = base + VA²·binStep/1e10`, cap 10%), но аккумулятор волатильности в сидах ~0 — динамическая часть дремлет. Помечено как backlog #14 (полный overhaul VA/L-единиц/анкора 2²³) |
| Стратегии Spot / Curve / Bid-Ask | ✅ | `StrategySelector` (Равномерная / Концентрированная / Двусторонняя) |
| Двусторонний депозит | ✅ | `addLiquidity(amountX, amountY)` |
| Односторонний депозит (только X или только Y) | 🔜 | Бэкенд требует обе суммы ≥1. Интегрируемо: ослабить валидацию + ветка распределения. ~1 день |
| Виджет создания позиции (диапазон бинов) | ✅ | Поля min/max бин + превью; перетаскивания-по-графику нет |
| Перетаскивание диапазона прямо на графике | 🔜 | UI-улучшение к bin-chart + слайдеру. ~1 день |
| Забор комиссий | ✅ | `fees.claimFees` |
| Комиссии в одном токене (quote-only fees) | 🔜 | Niche; настройка маршрутизации комиссии + тумблер. ~1 день |
| P&L позиции | ✅ | Колонка P&L (cost-basis `initialDepositX/Y`) |
| Список / управление позициями | ✅ | `/positions` |
| Ребаланс | ✅ | `/rebalance` |
| Авто-компаунд / авто-забор | ✅ | Auto-claim policy |
| Вывод по % (25/50/75/100) | ✅ | `removeLiquidity(percentageBps)` |
| Фарминг-награды активной ликвидности | 🔜 | Интегрируемо (эмиссия награды на in-range долю). Есть Spasibo-лояльность как другой стимул. ~3–4 дня |

## 2. Лимитные ордера 🆕

| Фича Meteora | Статус | Комментарий |
|---|---|---|
| Он-чейн лимитные ордера в пуле | 🆕 ✅ | **Реализовано escrow-моделью**: при размещении вход эскроуется (deduct), `LimitOrderFillWatcher` (@Scheduled 15с) исполняет по точной лимит-цене, когда рыночно-синхронизированная `basePrice` пересекает триггер (SELL: цена ≥ лимита; BUY: ≤); отмена возвращает эскроу. Резервы/бины пула не трогаются — своп-математика и F-12 не затронуты |
| Одно-биновый лимит | 🆕 ✅ | Одна лимит-цена |
| Диапазонный (до 50 бинов) лимит | 🔜 | Частичные исполнения по полосе цен — будущая мелочь поверх текущего |
| Заработок комиссий на лимит-ордере | ➖ | У Meteora лимит = ликвидность в бине и зарабатывает комиссию; наша escrow-модель проще и безопаснее (не возмущает инвариант пула) — сознательный компромисс для регулируемой платформы |
| Вкладки Positions / Limit Orders / History | 🆕 ✅ | Вкладка «Лимит» на странице пула (создание + открытые ордера этого пула) + страница `/orders` (все ордера, фильтр Все/Открытые/Исполненные/Отменённые, отмена) |

**Покрытие:** entity/repo/DTO/events + `LimitOrderService` (создать/список/отменить) + `LimitOrderFiller` (атомарное исполнение) + `LimitOrderFillWatcher` (планировщик) + контроллер (`/api/v1/pools/limit-orders`) + Liquibase 012 + init-db.
17 backend-тестов + 2 frontend. UI: `LimitOrdersPanel`, `OrdersPage`, навигация «Ордера», подсказка Сберкота.

## 7. Чего нет у Meteora, но есть у нас (дифференциаторы Сбера) 🟢

- **FX-хедж** для казначейства (`/hedge`).
- **Команда / B2B** мульти-пользовательский доступ (`/team`).
- **Сберкот** — AI-ассистент с контекстными подсказками по каждому экрану (+ интерактивность).
- **Реальный синк цен** (CoinGecko/ЦБ РФ) и **репрайс пула к рынку** (oracle → `PoolRepricer`).
- **Spasibo**-лояльность, **KYC/AML**, **SAML SSO**, self-restriction — регулируемый контур.
- **Отзывы**, **тарифы**, **Simple/Pro** режимы, ru-i18n.

## Итог

**Паритет по ядру DLMM (фичи 1–4, 9–10 из «headline» Meteora): достигнут.**
С интеграцией **лимитных ордеров** в этой сессии закрыт главный отсутствовавший headline-пункт 2026 года —
теперь правая панель пула повторяет триаду Meteora **Add Liquidity / Лимит / Своп**, плюс отдельная страница
управления ордерами.

**Интегрируемо и рекомендуется следующим (по убыванию ценности):**
1. Односторонняя ликвидность (только X/Y) — Meteora-core, ~1 день.
2. Zap in/out — ~2 дня.
3. Перетаскивание диапазона на графике — ~1 день.
4. Quote-only fees — ~1 день.
5. LP-фарминг-награды — ~3–4 дня.

**Сознательно неприменимо** (Solana-специфика / запуск мем-коинов / внешние DEX / governance-токен):
DAMM v2 + позиции-NFT, DBC, Alpha Vault/Presale, Anti-Sniper Suite, M3M3, Jupiter-агрегация,
Solana-кошелёк, MET/DAO/points. Для регулируемой платформы Сбера это не пробелы, а осознанный объём.
